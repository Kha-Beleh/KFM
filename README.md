# KFM

KFM запускается как обычное приложение в системе. В Docker работает только PostgreSQL.

## Запуск

Задайте `KFM_DB_PASSWORD` в файле `.env` и запустите БД:

```text
docker compose up -d db
```

В PowerShell:

```powershell
$env:KFM_DATABASE_URL='postgres://kfm:YOUR_PASSWORD@127.0.0.1:55432/kfm?sslmode=disable'
go build -o kfm.exe ./cmd/kfm
.\kfm.exe
```

В Linux:

```sh
export KFM_DATABASE_URL='postgres://kfm:YOUR_PASSWORD@127.0.0.1:55432/kfm?sslmode=disable'
go build -o kfm ./cmd/kfm
./kfm
```

В примере используется пароль без специальных символов URL. Для удалённой БД настройте TLS. Файл `.env` читает Compose; приложение получает настройки из переменных окружения.

## Пользователи и файлы

`register <login>` регистрирует пользователя, `login <login>` выполняет вход. Пароль вводится отдельно, в обычном терминале без отображения. `logout` завершает вход. Регистрация не выполняет автоматический вход.

Учётная запись KFM нужна для записи автора команды в журнал. Все вошедшие пользователи работают с обычными файлами системы в пределах прав той учётной записи ОС, которая запустила KFM. Дополнительных прав вход в KFM не даёт. Личные каталоги не создаются, `KFM_HOME` не используется, ограничения пользовательским корнем нет.

Текущий каталог при запуске определяется через `os.Getwd()`. `cd` меняет рабочий каталог KFM, `pwd` показывает его. Абсолютные пути, другие диски и относительные пути разрешаются по правилам ОС. Права на файл проверяет ОС.

`history` показывает последние 100 действий текущего пользователя. Журнал содержит команду, аргументы пути, время и результат, включая ошибки. Пароли и введённое содержимое файлов не записываются. Поле `owner_id` в метаданных связывает запись с действовавшим пользователем и не ограничивает доступ других пользователей к этому файлу.

## Команды

```text
help
register student
login student
ls [path]
cd [path]
pwd
drives
touch <path>
cat <path>
write <path> <n>
append <path> <n>
rm <path>
json-read <path>
json-write <path> <n>
xml-read <path>
xml-write <path> <n>
zip <source> <archive>
unzip <archive> <new-directory>
history
logout
exit
```

После команд записи вводятся `n` строк. Файл должен существовать; его можно создать через `touch`. При неполном или некорректном вводе запись не начинается. Поддерживается UTF-8, до 1 Мбайт на файл и до 10 Кбайт на вводимую строку. Запись добавляет LF после каждой строки. DTD в XML запрещены. Пути ZIP с пробелами заключайте в кавычки.

Ограничение каталогом назначения действует только при распаковке ZIP: архив не может писать за его пределами. Сам каталог назначения пользователь выбирает в любой доступной области ФС. Каталог должен быть новым. Лимиты ZIP: 1000 элементов, 10 Мбайт на файл, 20 Мбайт суммарно, 32 Мбайт на архив.

## Тесты

```text
go test ./...
go vet ./...
```

Интеграционные тесты требуют отдельной PostgreSQL с правом создавать схемы. Они используют временные схемы `kfm_test_*` и удаляют только их. Файловые проверки используют временные каталоги.

```powershell
$env:KFM_TEST_DATABASE_URL='postgres://kfm:YOUR_PASSWORD@127.0.0.1:55432/kfm?sslmode=disable'
go test -count=1 ./...
```

Без этой переменной интеграционные проверки явно пропускаются.

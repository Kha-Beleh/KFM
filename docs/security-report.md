# Проверка KFM после отмены личных каталогов

Дата проверки: 8 ноября 2026 года. Источники требований: «Семестровое задание №1.pdf» из `docs` и ранее предоставленная презентация «7 8 - угрозы Python.pptx». Проверялись классы угроз, а не достоверность приведённых в презентации CVE для Python.

## Модель доступа

Регистрация и вход определяют, какой пользователь выполняет команды. Они не создают отдельную файловую область и не предоставляют дополнительных прав ОС. Все пользователи KFM, запущенного от одной учётной записи ОС, имеют одинаковые возможности доступа к системным файлам. Это осознанная модель по требованию владельца проекта.

Рабочий каталог при запуске — каталог процесса. Абсолютные пути и переходы на другие диски разрешены, если их поддерживает ОС. Внутреннего пользовательского корня и переменной `KFM_HOME` нет.

## Реализованные проверки

| Область | Проверка и результат |
| --- | --- |
| Аутентификация | bcrypt с солью; пароль вводится отдельно и не включается в журнал |
| Авторство действий | Интеграционный тест: первый пользователь записывает файл, второй читает и удаляет тот же системный файл; журнал содержит соответствующие идентификаторы |
| Граница ОС | Никаких обходов отказа в доступе ОС; вход в KFM не меняет права процесса |
| SQL | Параметризованные запросы; запись метаданных и результата выполняется в транзакции |
| Чтение и запись | Проверки UTF-8 и размера; ввод собирается до изменения файла |
| JSON/XML | Разбор и сериализация; некорректные документы отклоняются до записи; DTD запрещены |
| ZIP | Запрет обхода пути, ссылок и повторов; ограничения количества и размеров; каталог назначения защищён через `os.Root` только на время распаковки |
| Разные системные пути | Отдельный тест создания архива из файла одного каталога и извлечения в другой независимый каталог |
| Терминал | Содержимое `cat`, имена файлов и сообщения журнала экранируют управляющие символы |

## Остаточные ограничения

* Прямое изменение системных файлов является разрешённой возможностью программы, а не изоляцией пользователей KFM. Ошибочно выбранный путь может привести к потере доступных процессу данных.
* Обновление ФС и запись в PostgreSQL не образуют общую транзакцию. При сбое завершения аудита после изменения файла требуется сверить его состояние, а не повторять команду автоматически.
* Запись текста заменяет содержимое существующего файла. Сбой диска после очистки может оставить частично записанный файл. Атомарная замена и блокировка внешних редакторов не реализованы.
* Метаданные отражают операции KFM; внешние изменения другими программами не отслеживаются. `owner_id` не является файловым ACL.
* bcrypt ограничивает пароль 72 байтами. Ограничение неудачных входов действует в пределах процесса.
* JSON-схема, XSD, шифрование ZIP и неизменяемый для администратора аудит не реализованы.
* Локальные проверки выполнялись на Windows с отдельным тестовым PostgreSQL. Нативное выполнение в Arch/Rocky Linux в этой проверке не проводилось.

Проверки выполняются командами `go test -count=1 ./...` с отдельной тестовой БД и `go vet ./...`. Отдельно тестируется отсутствие создания личных каталогов. Старые записи и файлы пользователей при откате исходного кода не удалялись.

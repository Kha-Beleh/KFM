# Тесты угроз из презентации

Источник: «7 8 - угрозы Python.pptx». Проверены применимые к KFM классы угроз, а не конкретные уязвимости библиотек Python. Фактическая дата запуска проверок: 8 ноября 2026 года.

Добавлено 26 тестовых функций: 21 без внешней БД и 5 интеграционных с PostgreSQL. Все новые функции имеют префикс `TestSecurity`.

| Слайды | Область | Файл и проверяемое поведение |
| --- | --- | --- |
| 5–7 | SQL-инъекции | `internal/postgres/security_test.go`: значения передаются отдельно от SQL. `internal/cli/security_test.go`: вредоносные строки не обходят поиск пользователя и не удаляют таблицы настоящей PostgreSQL |
| 8 | Инъекции команд | `internal/cli/security_test.go`: разделители `;`, `&&`, `&` в аргументе `touch` не запускают дополнительные команды |
| 9–14 | XXE, SSRF, расширение сущностей | `internal/structured/security_test.go`: запрет внешних сущностей и DTD, отсутствие обращения к локальному HTTP-серверу и раскрытия содержимого тестового файла |
| 15–19 | Конкурентные операции | `internal/filesystem/security_test.go`: при одновременном создании файла успешна одна операция, существующие данные сохраняются. `internal/cli/security_test.go`: повторное завершение одной записи аудита не меняет результат победившей транзакции; другой автор не может её завершить |
| 20 | Zip Slip | `internal/ziparchive/security_test.go`: пути с `..`, обратными слешами, диском Windows и UNC не меняют файл вне каталога распаковки; URL-кодированные сегменты остаются буквальными именами |
| 21–24 | ZIP-бомбы и опасные элементы | `internal/ziparchive/security_test.go`: ограничения количества и размеров, коэффициент сжатия, запрет ссылок, специальных файлов, ADS и зарезервированных имён Windows; удаление частично распакованных файлов после ошибки CRC |
| 26–28 | Пароли и перебор | `internal/auth/security_test.go`: независимая соль bcrypt, стоимость хеширования, длина пароля, повреждённые хеши. `internal/cli/security_test.go`: одинаковые сообщения для неизвестного пользователя и неверного пароля, блокировка после пяти неудачных входов, отсутствие пароля и хеша в журнале |

Дополнительно проверены пределы сложности JSON/XML, циклические структуры при сериализации, экранирование XML-текста, управляющих последовательностей терминала и сохранение исходного файла при некорректном вводе для записи.

## Результат запуска

Полный запуск `go test -count=1 ./...` с отдельной PostgreSQL завершился с одним падающим тестом: `TestSecurityZIPCompressionRatio`.

Архив содержит 4 000 000 распакованных байт при 3 998 сжатых байтах: коэффициент около 1000,50:1. Он принимается, хотя проверка задаёт порог 1000. В `internal/ziparchive/zip.go` используется целочисленное деление на `CompressedSize64 + 1`, из-за чего пограничное превышение теряется. Ограничения общего размера и размера отдельного файла при этом действуют. Реализация не исправлялась; тест оставлен падающим для воспроизведения дефекта. Если другая версия компрессора не создаст превышение порога для этого набора данных, тест явно пропускается.

Остальные запущенные тесты прошли. Проверка создания через существующую символическую ссылку пропущена: текущей учётной записи Windows недоступно создание таких ссылок. Проверка метаданных ссылок внутри ZIP выполнена и прошла. `go vet ./...` завершился без замечаний.

## Запуск

Из корня репозитория:

```powershell
go test -count=1 -run TestSecurity -v ./...
```

Для пяти интеграционных проверок задайте URL отдельной тестовой PostgreSQL:

```powershell
$env:KFM_TEST_DATABASE_URL='postgres://USER:PASSWORD@localhost:5432/TEST_DATABASE?sslmode=disable'
go test -count=1 -run TestSecurity -v ./...
```

Учётная запись БД должна иметь право создавать схемы. Каждая интеграционная проверка создаёт случайную схему, выполняет миграции и удаляет свою схему после завершения. Без переменной окружения интеграционные тесты явно пропускаются. При этой проверке использовался отдельный временный экземпляр PostgreSQL, а не основная БД пользователя.

## Границы проверки

Тест конкурентного создания проверяет конкретный сценарий, а не отсутствие всех TOCTOU-гонок. Проверки SQL с подставным драйвером проверяют передачу параметров; исполнение запросов и транзакций отдельно проверяется интеграционными тестами. Интеграционные тесты не являются юнит-тестами.

Шифрование ZIP из слайда 25 не реализовано и не проверяется. Тесты сообщений входа не доказывают постоянное время ответа. Принципы архитектуры и процессы разработки из слайдов 29–31 требуют отдельного анализа. Доступ к системным путям разрешён моделью KFM и не считается обходом изоляции пользователей.

Нативный запуск на Linux и проверка `go test -race` не выполнялись: в текущей Windows-среде нет C-компилятора для детектора гонок. Ни один из этих пропусков не считается успешной проверкой.
